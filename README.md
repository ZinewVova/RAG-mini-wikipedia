# RAG Wiki 

Данный проект демонстрирует реализацию RAG системы на примере корпуса из Википедии.
Цель — показать, как можно сочетать поиск по внешней базе знаний и генеративные возможности LLM для получения более точных и обоснованных ответов.


## Этапы проекта

### 1. **Подготовка данных**

   * Загрузка корпуса статей из Википедии
   * Очистка и токенизация текстов
   * Разделение на чанки.
     
В проекте используется адаптивное разбиение текстов на чанки, основанное на количестве токенов:
Если документ короче 400 токенов, он сохраняется целиком — чтобы не терять целостный контекст.
Если документ длиннее, он дробится на части по 200 токенов с перекрытием 50 токенов.

### 2. **Настройка retriever**

   * Используется модель *sentence-transformers/all-mpnet-base-v2* для создания эмбеддингов
   * Формирование векторной базы данных в Chroma
   * Добавление реранкера : *ms-marco-MiniLM-L-12-v2*

### 3. **Настройка генератора**

   * Используется модель **Qwen/Qwen3-8B** для генерации ответов
   * Квантизация модели. Тип квантования - NF4
   * Создание пользовательского промпта:
     
```bash
prompt_qwen = """You are a helpful and precise assistant. Your task is to answer the question based strictly on the provided context.
Follow these steps:
1. Carefully read the context and the question.
2. Inside the <thinking> tags, write down your step-by-step reasoning. First, extract the key facts from the context that are relevant to the question. Second, formulate an answer based ONLY on these facts.
3. After your reasoning, provide a final, short answer inside the <answer> tags. Very short answer!
4. If the answer is not present in the context, write "I don't know" in the answer tags and explain why in the thinking tags.

<context>
{context}
</context>

<question>
{question}
</question>

<thinking>
"""
```

## Анализ Результатов 

1.  **Context Precision (Точность контекста)**:
Ретривер **часто находит идеально релевантный контекст** (медиана 1.0). Однако среднее значение ниже (0.781) и стандартное отклонение довольно высокое (0.391), что вместе с наличием выброса (см. boxplot) указывает на то, что **иногда ретривер все же извлекает нерелевантные фрагменты**, которые снижают общую точность.
2.  **Context Recall (Полнота контекста)**:
Это **самая слабая метрика** в системе. Хотя медиана довольно высока (0.818), среднее значение самое низкое (0.709), а нижний квантиль (25%) всего 0.503. Это означает, что **ретривер часто не находит всю необходимую информацию** для полного ответа на вопрос. Именно недостаток полноты контекста, вероятно, является основной причиной ошибок в ответах.
3.  **Answer Relevancy (Релевантность ответа)**:
 Сгенерированные ответы **почти всегда соответствуют заданному вопросу** (медиана близка к 1.0). Как и в случае с `context_precision`, среднее значение несколько ниже из-за редких случаев, когда ответ уходит от темы, возможно, из-за некачественного контекста. Но в целом, генератор понимает, о чем его спрашивают.
4.  **Answer Correctness (Правильность ответа)**:
 Ответы **часто бывают фактически правильными** (медиана 1.0, 75% квантиль тоже 1.0). Среднее значение (0.776) достаточно высокое. Однако наличие значений в нижней части распределения (см. boxplot) и стандартное отклонение (0.390) говорят о том, что **иногда система дает неверные ответы**. Скорее всего, это напрямую связано со случаями низкого `context_recall`, когда генератору не хватило информации в контексте.

## Общий Вывод по RAG-системе 


* Она **успешно находит релевантный контекст** (`context_precision`) и **генерирует ответы по теме вопроса** (`answer_relevancy`), что подтверждается высокими медианными значениями этих метрик.
* **Фактическая правильность ответов** (`answer_correctness`) также часто высока.
* **Основное узкое место — это полнота извлекаемого контекста** (`context_recall`). Ретривер не всегда находит все необходимые данные, что является наиболее вероятной причиной для генерации неточных или неполных ответов.
